# Outbreak Monitor

A real-time disease outbreak surveillance dashboard that aggregates data from several public health sources into a single, self-contained web page. It displays US weekly notifiable-disease counts from CDC NNDSS, current respiratory virus activity for COVID-19, influenza and RSV (observed emergency-department burden alongside modeled transmission direction), a detailed breakdown of one current priority outbreak (with a live data-freshness indicator), and the 20 most recent Disease Outbreak News alerts from WHO — all rendered client-side with no backend or build step required.

**Live site:** [https://chrisv007.github.io/outbreak-monitor/](https://chrisv007.github.io/outbreak-monitor/)

## Data Sources

| Source | Attribution | What it provides |
|---|---|---|
| **CDC NNDSS** | Centers for Disease Control and Prevention, National Notifiable Diseases Surveillance System | Weekly case counts by disease and state, served via the Socrata JSON API. Instead of a fixed watchlist of diseases, the panel surfaces conditions by an outbreak *signal* computed from the data itself — a condition appears when its year-to-date count is clearly running above the same period last year, either as a strong proportional surge (≥20% up) or as a sustained rise (≥10% up) that carries a substantial number of excess cases, so both fast-growing new clusters and high-burden climbers are caught while flat endemic background is not. Newly emergent conditions (no cases in the prior-year period) are flagged "New." A new outbreak shows up automatically without a code change. On top of that trend signal, an **additive high-consequence severity tier** watches a deliberately narrow set of pathogens whose expected US baseline is essentially zero — epidemic-prone, high-lethality, bioterror, and elimination-target diseases (novel influenza A, viral hemorrhagic fevers, measles, plague, anthrax, diphtheria, polio, cholera, and similar) — because for those a single case is already anomalous and a trend/volume filter would otherwise bury them. Such a condition surfaces when it is emergent, active this week, or not declining (a quietly declining rare case is left to fall away rather than sit at the top with an alarm badge), and *active or rising* high-consequence signals are pinned to the top with a `⚠ High-consequence` badge. Matching is whole-word, so the bacterium name `Vibrio cholerae` in the common Vibriosis label does not get mistaken for cholera. Conditions with a real endemic US baseline (e.g. botulism, tularemia) are intentionally kept out of this tier — a genuine cluster of them still surfaces through the trend signal. This tier only ever *adds* a dangerous condition; it never gates what else the data-driven signal can surface, so it is not a return to the old name-based watchlist. A small diagnostic line under the section header reports how many conditions were evaluated, how many are running above baseline, and how many were flagged as high-consequence, so the selectivity of the signal is visible at a glance. National and regional rollup rows (e.g. `U.S. Residents`, `U.S. Total`, census-division groups) are filtered out client-side so headline totals are not double-counted against the per-state rows. Minnesota is pinned and highlighted in every state breakdown, with a dedicated Minnesota year-to-date tile in the summary bar. |
| **CDC NSSP ED visits** (`rdmq-nq56`) | Centers for Disease Control and Prevention, National Syndromic Surveillance Program | **Observed burden** for COVID-19, influenza and RSV: the weekly share of all emergency department visits attributable to each pathogen, by state and sub-state region, with the feed's own increasing/decreasing/no-change trend. These are percentages, not case counts. Sub-state rows are filtered out client-side so states are not double-counted, and Minnesota is pinned and highlighted in the state table. |
| **CDC Epidemic Trends and Rt** (`5dqz-y4ea`) | CDC Center for Forecasting and Outbreak Analytics | **Modeled direction** for the same three pathogens: Rt with an uncertainty interval, a trend category, and probability of epidemic growth, nowcast so it leads the observed series. Rendered as visibly modeled, never mixed in with observed surveillance, and never presented alone: Rt is direction only and an Rt below 1 does not mean activity is low. Flu and RSV Rt is estimated seasonally (roughly October through May), so outside that window the panel shows an explicit off-season state rather than an error or a zero, and the dashboard distinguishes that expected pause from a genuinely stale feed. "Not estimated" (the model declined for a state) is shown distinctly from "no data" (the state is absent). Only estimates from the current method are shown, so no series spans the 1 June 2026 EpiNow2 to hierarchical-GAM methods break. Note that this and the NSSP feed above share the same upstream ED data, so they are burden versus direction, not two independent confirmations. |
| **Global Priority Outbreaks** | Source varies by featured outbreak (currently the [Global.health](https://global.health/) Ebola BVD 2026 line list for Ebola BDBV 2026, **CC BY 4.0** — Global.health is a data aggregator, not itself a health authority, so the section carries an explicit attribution and license note) | Detailed breakdown of one current high-priority outbreak. For the current Ebola featured slot this is a **record-per-case line list** covering every affected country in one file: confirmed-only case and death totals grouped **dynamically by country of case location** (so new countries and international imports surface on their own, with attribution following case location rather than nationality or travel history), a preserved health-zone drill-down for the largest affected country, and a live/stale data-freshness banner — driven off the file's own last-modified dates — that signals when the feed needs replacing |
| **WHO DON** | World Health Organization, Disease Outbreak News | Official outbreak alerts and situation reports |

## Architecture

The entire application is a single `index.html` file. It uses vanilla JavaScript to fetch data from the sources above at page load, in parallel and with per-source error isolation so one failing feed never blanks another, then builds and inserts DOM elements directly. There is no framework, no bundler, no npm install, and no server component. Deploying the dashboard means serving the file via GitHub Pages or any static host.

The respiratory section resolves its column names **at runtime** rather than hardcoding them: each field is a candidate list, and the code probes the dataset and binds to whichever column actually exists. This is deliberate. `data.cdc.gov` is unreachable from the environments this project is developed in, so those two schemas could never be confirmed with a live request, and a guessed schema would otherwise fail silently as blanks or zeros. If a required field cannot be resolved the section renders a loud error listing the real column names the API returned, and a diagnostic line under the section header always reports what was resolved. See CLAUDE.md before changing any field name.

The footer shows a **"Dashboard page last modified"** timestamp (Central time). This is a static string set by whoever last edited `index.html` — it is not computed from the visitor's clock or from data-refresh time, and it does not update on its own. Its only purpose is letting you compare the live GitHub Pages site against the latest commit to confirm the deploy has caught up. See CLAUDE.md for the update rule.

## Contributing

Before making any changes, read **[CLAUDE.md](./CLAUDE.md)**. It contains the persistent project context that Claude Code loads at the start of every session, including confirmed API field names, critical query patterns for each data source, and lessons learned from past bugs. Any pull request that touches an external API endpoint should include evidence (a live curl response) that the new query returns real data. Where the host is unreachable from the development environment and that evidence cannot be produced, CLAUDE.md sets out the required fallback: candidate field lists bound at runtime, a loud failure that names the real columns, and the resolved schema printed onto the live page.
